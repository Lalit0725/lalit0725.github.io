Universal Field Bridge

A shared data boundary between industrial devices and the applications that need their state.

Role: Unity & Digital Twin Engineer · Timeframe: 2023–2024

Python asyncio WebSockets Modbus OPC UA Siemens S7 SQLite

What this means for you

When plant protocols vary, a normalised gateway gives downstream applications one consistent stream to consume, with local buffering designed to support disrupted connectivity.

Context & problem Constraints Approach & architecture Implementation Challenges & how they were solved Outcome Technology

Context & problem

A blending unit at a national oil and gas operator exposed data through different device protocols. Applications otherwise had to interpret vendor-specific addresses themselves, making integration repetitive and fragile.

Constraints

The gateway had to work across Modbus, OPC UA, and Siemens S7 while keeping device details out of clients. Continuous flow and connection changes had to be treated as normal operating conditions.

Approach & architecture

Protocol adapters pass readings into a configuration-driven normalisation layer. Named tags are published in a shared namespace and serialised as JSON for WebSocket clients; SQLite is used as an edge buffer designed to support retention across a connection drop.

Implementation

Python asyncio coordinates non-blocking polling and client broadcast. WebSockets expose the normalised stream to real-time consumers, including a Unity process twin, while the local store supports buffering around link failures.

Challenges & how they were solved

The key challenge was separating field-protocol variability from visual and analytical clients. A semantic layer and asynchronous transport let clients subscribe to tags rather than interpret registers, while buffering supports changing connectivity.

Outcome

The gateway provides a common data stream and a clearer boundary between industrial hardware and software that visualises or uses its state.

Technology

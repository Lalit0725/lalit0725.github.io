Decoupled four-part notification engine

The package separates the trigger call site from visual element instantiation, thread marshaling, and styling concerns.

01 / THREADING Thread Safety

Automatic Main-Thread Marshaling

Unity UI Toolkit elements cannot be touched from background threads. The dispatcher captures the main thread's SynchronizationContext at startup, seamlessly routing calls from async tasks, websockets, and worker threads without throwing thread-access exceptions.

Zero scene setup or manual Dispatcher boilerplate needed by callers
02 / MEMORY Zero-GC Allocation

VisualElement Hierarchy Recycling

Instantiating and destroying UXML nodes for rapid alerts creates garbage collector spikes and frame stutter. An internal object pool reuses pre-built VisualElement trees, resetting text, icon, and progress bindings before returning elements to the pool upon dismissal.

Zero steady-state heap allocations during continuous alerts
03 / LIFECYCLE Queue & Stacking

FIFO Stacking & Auto-Dismissal

Coordinates layout positioning, maximum concurrent active toast limits, and sequential entry/exit animations. Each notification manages its own lifetime timer and progress indicator, with support for interactive click-to-dismiss overrides.

Gracefully prevents toast flood from overwhelming the viewport
04 / PRESENTATION USS Separation

Pure Stylesheet Theming

Visual presentation is isolated into Unity Style Sheets (USS). Colors, margins, border radii, transitions, and status variants (Info, Success, Warning, Error) are controlled via CSS-like classes without changing or recompiling C# code.

Designers can customize visual themes without engineering intervention

Call-site simplicity with zero boilerplate

Compare the traditional ad-hoc notification approach with the clean static API provided by the package.

✕ Without Package (Scattered & Fragile)

Callers must hold references to scene canvas/visual trees, manually instantiate prefabs or UXML templates, manage coroutines for dismissal, and handle thread safety errors.

// Requires scene reference & coroutine runner
var uiDoc = FindObjectOfType<UIDocument>();
var el = toastUxml.Instantiate(); // Allocates GC
uiDoc.rootVisualElement.Add(el);
StartCoroutine(DismissAfterDelay(el, 3f));
⚠️ Throws UnityException if called from background thread
High coupling · GC allocations on every trigger · Fragile threading
✓ With Toast System (Single Clean Call)

Callers invoke a static entry point from anywhere in the codebase. Thread dispatch, element pooling, layout positioning, and auto-dismissal run autonomously.

// One line from any game system or UI component
Toast.Show("Parameters saved successfully", ToastType.Success);

// Custom duration and warning status
Toast.Show("Sensor connection degraded", ToastType.Warning, 4.0f);

// Completely safe from background threads or async tasks
Toast.Show("Sync complete", ToastType.Info);
Zero boilerplate · Thread-safe auto dispatch · Recycled elements
